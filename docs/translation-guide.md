## 0. 結論（先に）

1. **Zork II・III の訳は、仕組みの側の仕事がほぼ無い。** あるのは ① 抽出器と生成器が `zork1` の名前を固定で持っていること
   ② 字の範囲の検査が Zork I だけを見ていること、の 2 点だけ（→ 5 章）。
2. **同じ英文は Zork I の訳がそのまま使える**（ID が「正規化した英語の SHA-1」）。ただし**埋まるのは 2〜3 割**で、原簿を起こして数えた実数は
   **Zork II が未訳 1,304 件・Zork III が 922 件**（段 1）。4 章の「約半分」は文字列だけの概算で、少なすぎた。
3. **★再配布の条件は、訳の側にも及ぶ。** JSON もパックも照合キーに**英語の原文そのもの**を持つので、原作が再配布不可なら訳も配れない（→ 6.4）。
   Zork I〜III は MIT なので問題ない。
4. **「パックを全部の版で共通の入れ物にする」ことは勧めない。** 共通にすべきなのは**中間の JSON（`assets/<作品>-*.json`）と生成器**で、
   これは既に共通。パックは PC-98 向けの**派生物**として置いておく。（→ 6 章）

## 1. Zork I で通った道

```
ZIL ソース（MIT）                                  手で書く側（原簿・非公開）
  │ 抽出器が TELL/PRINTI/DESC… の文字列を機械で抜く      zork1-ja.md        定型文の訳（ID・原文・訳文）
  ▼                                                     zork1-assembled.md 完成行（複数の TELL にまたがる文）
英語の一覧（ID = 正規化した英語の SHA-1 先頭 8 桁）────>  zork1-cmd-ja.md   入力語彙（日本語 → 英語コマンド）
                                                        zork1-guide.md     原作に無い言い方への案内
  zork1_asset.py build ──> assets/zork1-ja.json   （訳・ふりがな）
  zork1_cmd.py   build ──> assets/zork1-cmd.json  （入力語彙）
        │
        ├─ Web: src/translate.js・command.js・ruby.js が JSON をそのまま読む（★正典）
        ├─ PS1 / SDL: native/gen_*.py が C に焼く（*_data.c）
        └─ PC-98: 同じ生成器が ctab.py で節を出し、gen_pack.py が ZORK1.ZMP に束ねる
```

### 1.1 しくみの芯（Zork II・III でも変えない）

| 芯 | 内容 | 理由 |
|---|---|---|
| ★**英語は必ず ZIL から抽出** | 人が触るのは訳文だけ。原文を手で書き写す経路を作らない | 転記ミスがそのまま「訳が出ない」欠損になる |
| ★**照合は行単位** | 出力を改行まで貯め、英語の**完成行**をキーに日本語を引く | 1 行が複数の印字呼び出しに割れ、日本語は述語が最後に来る（`Opening the X reveals …`） |
| 実行時の機械翻訳は使わない | 事前に訳した完成文の辞書引き | 毎回同じ訳・オフライン・軽い |
| 入力は「閉じた命令言語への翻訳」 | 日本語を解析せず、原作の語彙（動詞 135・前置詞 18・目的語 2）へ写す | 曖昧解消・複数対象・代名詞・聞き返しは**原作が持っている** |
| 1 語 = `表記(よみ)` | 第一読みがふりがな。`×` 後置はルビ専用 | 読みは推測せず宣言する（ふりがなの無い漢字を 0 にできた） |
| 上位語は宣言 | 扉・箱・舟…は専用の表。`名詞` があれば語を渡すだけ | その場に無い物を名指しして外れるのを避ける |

### 1.2 原簿の 5 つの表

| 原簿 | 書き手 | 中身 |
|---|---|---|
| `zork1-ja.md` | **自動生成（訳文欄だけ人）**。`refresh` で作り直す | 定型文・部屋名・物の名前の訳。`—` は訳さない行（デバッグ・版権） |
| `zork1-assembled.md` | **手書き** | 完成行（`{PRSO}` などのスロット入り）。日本語は述語が最後なので分岐語が文末へ移る |
| `zork1-cmd-ja.md` | 自動生成（日本語欄と「上位語」「コマンド不適語」だけ人） | 前置詞・動詞・物・上位語・不適語 |
| `zork1-guide.md` | 手書き | 原作に無い言い方（「つかう」「ねる」）への案内 |
| `zork1-ruby.md` | 手書き | 本文に出る**難読語**の読み（物の名前の読みは入力語彙から自動。出ない語を書いてもふりがなは付かない） |

文体は浅羽莢子訳（『火吹き山の魔法使い』）系の常体・淡々・「きみ」は主体が曖昧な文だけ。**疑問符の原則**（反語は句点・名詞句の困惑は「？」）と
**不適切な語の原則**（語り手が偏見を語る箇所は言い換え、登場人物の口の悪さは残す）は `zork1-templates-ja.md` の冒頭にある。
★Zork II・III でも**同じ方針を引き継ぐ**（同じ語り手のため）。

## 2. 踏んだ失敗と対策

★「穴は静的な監査では見つからず、**実プレイが見つける**」が 3 回続いた。だから**検査の分母を機械で作る**のと、**実プレイの未訳ログを残す**のを両方やる。

### 2.1 出力側（訳）

| 症状 | 原因 | 対策 | 次の作品への教訓 |
|---|---|---|---|
| 複数対象で `brown sack: Dropped.` が英語のまま | 行単位の引きで、頭に名前が付いた瞬間に在庫から外れる | 名前と本文を**剥がして両方引き、組み直す**規則を 1 本。**両方引けたときだけ**成立（片方でも欠けたら未訳のまま出す） | 「件」ではなく「類」で手当てする。未訳ログにこの形が出ても在庫に足さない |
| `The troll … catches the X and … eats it.` が英語 | 頭も尾も既存の文なのに、**組み合わせの完成行が無かった** | 完成行 A-26 を追加 | 断片が揃っていても完成行は別に要る。★audit も fragment_check も 0 件と言う → **実プレイでしか出ない** |
| 戦闘メッセージが出ない | 入れ子 `LTABLE` の中に `F-DEF` / `F-WEP` のトークンが挟まる乱数表 | ソースから機械的に 99 種を導いて完成行に | 乱数表は一度の走行では全部出ない。**走行ではなくソースから数える** |
| `I don't know the word "!)".` が外れる | 引用符の中のスロットに記号が入る | 引用符で囲まれたスロットだけ `[^"]*` | 引用符の中は**打った語そのもの**。訳さない |
| `a clove of garlic, and a lunch` が英語のまま | 行としては引けているので未訳に数えられず、監査に映らない | 並びは**全部引けたときだけ**「と」で繋ぐ。`rawWords` で「スロットに残る英語」を数える | 「引けた行数」でなく「スロットに残った英語」を数える |
| `You can't see any window here!` の window が訳せない | パーサが打った語を復唱する。props（DESC）ではなく**辞書の裸の名詞** | 語訳（`words`）を別に持つ | パーサの復唱に出る語は props と別系統 |
| 「ビニールの塊」を指したのに「穴の空いた舟など…」 | 3 つの舟が plastic / boat / pile を共有。原作に一意な指し方が無い | 原作が**入力バッファを印字する**行（`BUFFER-PRINT`）は `{SAID}`（打った語）で返す。`D ,PRSO` は `{OBJ}`（原作の呼び名） | 「原作が何を印字しているか」で `{OBJ}` と `{SAID}` と `{ECHO}` を分ける |
| 轟音の部屋の反響が `north north …` のまま（PS1 だけ） | 照合の探索を 1 回で打ち切っていた。JS は正規表現でバックトラックする | C の `match_pat` を再帰に | ★**JS に有る挙動が C に無い**。同値コーパスに**この形が載っていなかった**ので素通りした |
| 峡谷で「およぐ」と文字化け（`o xufpIt's`） | 原作 `V-SWIM` が目的語なしで空の物に `D ,PRSO` を呼ぶ原作の不具合 | **送るコマンドの側**で `swim in water` にする（外れたときの別案つき） | 原作の不具合は訳では直せない。コマンド層で避ける |
| 画面の字が `\|` で割れる / 行頭の字下げが消える | ZIL は文字列中の改行を `\|` で表す／入れ子の字下げ | `\|` を境に英日を対で割る・字下げを訳文に戻す | 読み物は行単位で引けるように割る |

### 2.4 画面・検査リグ（訳以外で訳に響いたもの）

- ★**禁則と語の途中で割らない**: 「ASCII でない」≠「どこでも折れる」。語を作る字は割らない（`152577c`）。等幅を前提にした数は持たない

### 4.1 作品固有の注意（2026-10-05 に Zork II の ZIL を読んで調べた）

#### 呪文（Zork II）

- ★**呪文の語は 17 語、`gsyntax.zil` の `BUZZ`（パーサが読み捨てる語）として辞書に入っている**:
  `FEEBLE FUMBLE FEAR FILCH FREEZE FALL FRY FLUORESCE FERMENT FIERCE FLOAT FIREPROOF FENCE FUDGE FANTASIZE` + `FROTZ OZMOO`（この 2 語は Zork III にもある）。
  構文（`SYNTAX`）は作品の側には無く、共有の `gsyntax.zil`・`gverbs.zil` にあるだけ（Zork I の `gverbs.zil` にも呪文の分岐は入っているが、杖が無いので出ない）。
- ★**呪文は「語」であって「構文」ではない**。流れ: `WAVE WAND AT 物`（`WAND-ON` が物になる）→ `INCANT`（= `CHANT`）で、`V-INCANT` が
  **次の節の先頭の語**（`P-CONT`）を `SPELL-USED` に取る → `V-ENCHANT` が物に効果を出す。節は **`THEN` / 句点 / 引用符**で割られる（`gparser.zil:262-273`）。
  つまり呪文名は**辞書の英語の語でなければならない**（原作の語彙は変えられない）。★**打ち方の正確な形（`incant "feeble"` か `incant. feeble` か）は未確認** —— 実機で確かめる。
- 呪文の**効果の文**は普通の文（`The wand stops glowing…`・`A strong odor of chocolate permeates the room.`・`Filched!`）で、通常の手順で訳せる。
  ウィザードが唱える呪文（`He says "Fear!"` など・`2actions.zil:3435` ほか）は**呪文名が文の中に出る**ので、訳文の中の呪文名の表記を入力側の表記と**揃える**必要がある。
- ★**決めた（msonrm・2026-10-05）: 呪文名は日本語の日常語で、頭音を「こ」にそろえる。** 英語の F を「ふ」に写す案（ふにゃれ・ふるえろ…）も出したが、
  F の理由が原作に書かれていない以上、**日常語で効果が直結すること**を優先した。品詞は英語に倣って**そろえない**（命令形・名詞・慣用句が混ざってよい）。

  | 英語 | 呪文 | 英語 | 呪文 | 英語 | 呪文 |
  |---|---|---|---|---|---|
  | FEEBLE | こしぬけろ | FREEZE | こおりつけ | FRY | こげろ |
  | FUMBLE | こぼれおちろ | FALL | こけろ | FLUORESCE | こうこうとひかれ |
  | FEAR | こわがれ | FLOAT | こうどをとれ | FUDGE | こりゃあまかった |
  | FERMENT | こんらんしろ | FENCE | こばめ | FIREPROOF | こげるな |
  | FIERCE | こうふんしろ | FILCH | こそどろ | FANTASIZE | こころここにあらず |

  - ★FERMENT は「こうぼきん」も出たが、**効果（酔ってふらつく・違う方向へ行く）に直結する「こんらんしろ」**にした（ドラクエ・FF の「混乱」で馴染みがある）。
  - ★FLOAT は短く「こうどをとれ」・FIREPROOF は「こげるな」（Fry の「こげろ」と対）。FUDGE の「こりゃあまかった」は、**失敗の口癖と甘い匂いの二面を 1 つの語呂で取った**（msonrm の案）。
  - ★**実装上の約束**: 呪文は動詞＋目的語に分けて解析せず、**呪文の語彙表の固定句**として `incant` の後の節でだけ引く（助詞を含む句があるため・「こおり」など日常語との衝突を避けるため）。
    言い換え（浮かべ・ふわり など）も同じ表に載せ、**表示（ウィザードの詠唱・訳文）は上の正規の語にそろえる**。
  - ★「こう」始まりが 4 語ある（こうふんしろ・こうどをとれ・こうこうとひかれ・こころ…は「ころ」）。入力の食い合い検査（`run-swallow.js`）に載せて確かめる。

#### 呪文 15 語の意味と効果（2026-10-05・`2actions.zil` / `gverbs.zil` から）

★呪文は 2 系統ある。**ウィザードがプレイヤーにかける 12 語**（`SPELL-NAMES`・効果は `SPELL?` で持続し、切れると `SPELL-STOPS` の文が出る）と、
**杖でプレイヤーが物・人にかける**語（`V-ENCHANT`）。杖の効果は対象が人（`ACTORBIT`）なら多くが「効いたか分からない」止まりで、**物に効く語は 5 つだけ**。

| 語 | 英語の意味 | 品詞の形 | プレイヤーにかかったとき（ウィザード） | 杖で対象にかけたとき | 切れたとき |

| FEAR | 恐怖 | 名詞/動詞 | ウィザードが恐ろしく、部屋から逃げ出す（ランダムに歩く） | 人: 怯える・部屋に怪物がいれば逃げる | 「ウィザードはそれほど怖くない」 |

| FENCE | 柵 | 名詞/動詞 | 見えない力の柵で歩けない | 人: （効果の記述なし） | — |

#### 杖と呪文の入力（★2026-10-05 に Zork II を走らせて確かめた）

検査用のハーネス（`tools/play-en.js`・`WORK=zork2 node tools/play-en.js "!^magic wand$" "take lantern" …`）で、杖を持ち物へ移して英語で試した。

| 打つもの | 結果 |
|---|---|
| `wave wand at lantern` | 「杖が温かくなり、ランプが魔力の光でぼんやり光る」＝ **対象を選ぶ**（`WAND-ON` が対象になる） |
| `say "float"` / `incant "float"` / `chant "float"` | **呪文が効く**（`The lamp floats serenely in midair.`） |
| `say float`（引用符なし） | 杖は光るが「はっきりした効果はない」＝**効かない**（語が次の節として取れない） |
| `float`（語だけ） | `There was no verb in that sentence!` |
| `say "xyzzy"`（辞書に無い語） | 受け付けるが効果なし。**辞書にある 15 語だけが効く** |
| `rub lantern with wand` / `brandish wand at lantern` | `wave wand at …` と同じ（同義の言い方） |
| `wave wand`（対象なし） | `At what?` ／ `wave wand at me` → 安全装置で拒まれる |
| 続けて `wave wand at …` | **充電中**。通常は「魔法の杖は使ったあと充電に時間がかかる」と断られ、**5% で杖が爆発して死ぬ**（約 10〜19 手で再び使える） |
| `say "feeble"` を物に | 「何か起きたかもしれないが、ランプでは分からない」（物には効かない語は多い） |

- ★**流れは 2 段: `wave wand at 物` →（杖が光る）→ `say "呪文"`**。呪文は**引用符の中**（パーサが引用符で節を割り、`V-SAY` / `V-INCANT` が次の節の語を読む）。
- ★**日本語の入力 → 原作の入力**: 「つえをランタンにふる」→ `wave wand at lantern`（通常の動詞）。「こうどをとれ」（または「…と唱える」）→ **`say "float"`**（固定句の表・実装済み = `src/command.js` の `spells` / `test/run-spell.js`）。
- ★**日本語版の引用符はカギカッコ**: 正規の打ち方は **「こおりつけ」と唱える**（画面のエコーもこの形）。**カギカッコも「と唱える」も省いてよい**（`こおりつけ` だけでも通る・全角の括弧・感嘆符は外して照合）。
  訳文の側も同じで、ウィザードの詠唱（`He says "Fear!"`）は「こわがれ！」とカギカッコで訳す。
- ★**呪文を単独で打ってよい**（引用符も「唱える」も要らない）。杖が光っていないときに打つと、原作は「独り言は精神崩壊の前兆だ」と返す（原作の応答のまま）。
- ★**C への写しは未**（`native/cmd.c`・`cmd_data` に `spells` の道が無い）。JS が正典。PC-98 のパックの `CMDS` 節にも呪文の表を足す必要がある。
- ★**進め方（msonrm 2026-10-05）: JS を固め → Web で確かめ → 他の版へ写す**。Web は `?work=zork2` で作品を選べる（下の「Web で作品を試す」）。

★**入力の約束（msonrm 2026-10-05）: 一般の入力は終止形のまま、命令形は足さない。** このゲームは**プレイヤーが主人公として行動する**ものであって、
主人公に指示を出すものではない。「ふくろをあける」はプレイヤー自身の行動で、「あけろ」は誰かへの指図になる。**命令形を受けるのは、別の存在へ向けた言葉だけ**:
呼びかけ（「ろぼっと、きたへいけ」）と呪文（「こおりつけ」）。

- ★**分かったこと（直していない）**: でたらめな日本語を大量に流すと、入力層が**形に合わない動詞へ目的語を付けて送る**（`stand menhir`・`dig menhir in lid`）ことがある。原作は「その文は知らない形だ」と返すだけで害は小さいが、**形が無いなら入力層で断る**のが筋（JS と `cmd.c`・Zork I も同じ）。

## 6. パックを他の版と共通にすべきか

### 6.1 いまの形

| 版 | 訳・語彙の入り方 | 作品の選び方 | story |
|---|---|---|---|
| Web | `assets/*.json` を fetch（`web/main.js`） | 固定（Zork I） | `vendor/zork1/zork1.z3` を fetch |
| PS1 | `*_data.c` に**焼き込み** | 固定（ビルド時） | `story.bin` を焼き込み（`build.sh`） |
| SDL2（PortMaster） | `*_data.c` に焼き込み | 固定（ビルド時） | `story.bin` を焼き込み |
| PC-98 | パック `ZORK1.ZMP` の節を起動時に読む | 起動画面で選ぶ | `ZORK1.Z3` を別に置き、識別で探す |

★どの版も**元は `assets/*.json` 1 組**。`ctab.py` が「1 つの定義から `*_data.c`・`*_tab.c`・節を出す」ので、**バイナリの共通化は生成器の段で既に済んでいる**。

### 6.2 判断

★**パックを共通の入れ物にはしない。共通にするのは JSON と生成器。** 理由:

1. **パックの形は PC-98 の事情で決まっている**。メモリが小さく（拡張 2MB・59KB 以下の塊）、ファイルで作品を渡したく、story を分けたい。
   他の版にこの事情は無い。**Web は JSON が読めて、読むだけで済む**（パックにすると JS に 2 つ目の読み口が要り、★正典を JS から動かせる 2 つ目の道を作ってしまう）。
2. **PS1 は 1 本の `.psexe`**。起動時にファイルを読む道（CD）を足すより、**作品ごとにビルドして焼く**ほうが単純で、実機の 1 度きりの検証に載る。
3. **正典は JS**（`CLAUDE.md`）。C のパック読み（`tabload.c`）は移植で、ここを共通の要にすると「直すときは両方を見る」の負担が 2 倍に増える。
   `translate.js` の挙動を C で再現する検査（4,031 件）は、すでに**パックを経由しても同じ**ことを PC-98 で確かめている。
4. **Zork II・III の訳は版ごとに作り直さない**。作品の JSON を 1 度作れば、全部の版が同じ訳を使う。パックにする・焼く・fetch するは**運び方の違い**でしかない。

### 6.3 共通化するなら（優先順）

| 優先 | 内容 | 理由 |
|---|---|---|
| 1 | **作品名を引数にした生成器**（`gen_*.py --work zork2`）と **`assets/<作品>-*.json`** | 全版に効く・段 0 の 2 |
| 2 | **字の範囲の検査を作品ごとに**（`gen_pack.py` / `pc98_jis.py`） | PS1 の字形焼き（`gen_data.py`・KH フォント）にも効く。★KH フォントはこの機械に無い |
| 3 | **Web 版で作品を選ぶ**（`TODO.md` の E）。パックでなく **JSON を作品ごとに** fetch すれば足りる | 版の入口を揃えるだけ。パックの読み口は要らない |
| 4 | SDL が作品を選ぶ必要が出たら、そのとき**パックを読む**（`glibc` があるので `tabload.c` が使える） | 今は PortMaster 申請が先。Zork I だけの配布で足りる |
| ✗ | PS1 に作品選択を足す | 検証が重く、見合う効果が無い。作品ごとに別ビルドで済ませる |

★**迷ったら**: 「JSON が正典・パックは派生」という向きを崩さないこと。パックから JSON へ戻す道（逆）を作ると、`assets/*.json` を直しても戻らない種類の事故（原簿の自己汚染）が再演される。

### 6.4 配布の条件 —— 訳の束には原文が入っている（2026-10-05 確認）

★**以前の説明（「story を分けたので訳の束だけなら配れる」）は不正確だった。** story を分けても、訳の側に原文が残る:

| 場所 | 原文を持つ所 |
|---|---|
| `assets/<作品>-ja.json` | `exact`（キーが英語の原文全文・長い読み物も段落ごと）・`templates` / `assembled` / `fragments`（`en`）・`props`・`words`・`notrans` |
| `assets/<作品>-cmd.json` | 英語のコマンド語（文章ではなく原作の語彙の語） |
| パック `*.ZMP` の TRAN 節 | 英語の文字列プール（`tr_en_pool`）。★`gen_translate.py` が JSON から作る |
| PS1 / SDL の `*_data.c` | 同じ表を焼き込んでいる |

照合は「英語の完成行をキーに日本語を引く」ので、**原文を持たずには今の形では動かない**。

- Zork I〜III は **MIT**（Microsoft・2025-11-20）。配布物に `LICENSE` を置いており（Release の `ZORK1.TXT` ほか・`build.mjs`・PortMaster の `licenses/`）条件を満たす。**今は問題ない**。
- **MIT でない作品へ広げるとき**: 訳の束も再配布の対象になりうる（派生物の扱いは法的な判断で、ここでは断定しない）。
  対処の案 = **キーを英語の ID ハッシュに置き換え、原文を持たない形にする**。
  - ID はすでに「正規化した英語の SHA-1 先頭 8 桁」。`exact` / `props` / `words` のキーを（衝突を避けて長めの）ハッシュにし、実行時に VM の出力を同じ正規化でハッシュして引く。
  - 難所は**スロット付きの骨格**（`The {PRSO} is closed.`）。正規表現として英文の形を持つので、ハッシュでは引けない。完成行を「ハッシュの列」にする案もあるが実装が大きい。
    骨格が原文に当たるかは法的な判断。
  - ★JS（正典）・C の `translate.c`・`gen_*.py`・`ctab.py`・パックの書式（schema）すべてに響く大きな変更。**必要が出たときに設計する**（いまは作らない）。
