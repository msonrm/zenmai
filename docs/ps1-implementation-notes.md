# Zenmai PS1 版 実装ノート

**状態: 段階 1〜5 完了・遊べる**（2026-08-21）。計画は `ps1-port-plan.md`、こちらは
**実際に作って分かったこと**を置く。計画に書いてあって変えなかったことは繰り返さない。

配布物は `native/zenmai-zork.psexe`（起動時に 日本語 / ENGLISH を選ぶ統合版・632KB）。
残る段階は **6. 実機 CRT** だけ。

## 1. どう組んだか

`psyqo` も pcsx-redux も使わなかった。**フリースタンディングの C を直接 PS-EXE に固める**
形（`link.ld` + `pack_exe.py`）で、SDK 依存はゼロ。理由は、要るものが GPU への
コマンド送出とパッド読みだけで、SDK を入れるほうが遠回りだったから。

| 層 | ファイル | 出どころ |
|---|---|---|
| 描画・パッド | `render.c` / `render.h` | 新規 |
| ルビ分節 | `jp_text.c` | web の `ruby.js` を移植 |
| 訳 | `translate.c` + `translate_data.c` | web の `translate.js`（JS が正典） |
| かな → コマンド | `cmd.c` + `cmd_data.c` | web の `command.js`（同上） |
| 入力状態機械 | `input.c` + `tables.h` | GamepadEngine の `machine.ts` |
| Z-machine | `vendor/mojozork.c` | MojoZork f94c3104（zlib）+ パッチ |
| mini-libc | `lib.c` | 新規（mem/str・vsnprintf・LIFO アリーナ malloc） |
| 本体の main | `main.c` | —— |
| 描画ゴールデンの台 | `demo_main.c` | 段階 1 の日本語デモ。`build-demo.sh` で焼き、`golden.py` の出力と画素照合する |

`_data.c` 系は `gen_*.py` が web の資産から生成する。**JS 側が正典**なので、訳や語彙を
直したいときは web を直してから再生成する（配布物だけ直すと次の生成で戻る）。

★**生成ヘッダはリポジトリに追跡している**。`glyphs.h` は KH ドットフォント（同梱していない）
が無いと作れないので、無視すると clone しただけではビルドできなくなる。

## 2. 検証リグ —— R3000 シミュレータ

実機もエミュレータも自動検証には使えないので、**`sim.py` に MIPS I を手書きした**。
命令の実行に加えて GPU コマンド列（`0xA0` 転送・`0x02` 塗り・`0x80` 面内コピー）を
解釈して仮想 VRAM を組み立て、最終画面を PNG にする。`--expect` でゴールデンと画素比較。

```
sim.py zenmai-zork.psexe --script dual_ja.script --polls --stop 4400 --max 400000000 --png out.png
```

- **台本の時間軸は `--polls`（パッドのポーリング回数）にする**。フィールド数だと処理の
  重さで台本がずれる。ポーリング回数は「ゲームが入力を待っている回数」なので、
  変換に時間がかかっても台本は追従する（閉ループ）
- ★**`--stop` も `--polls` のときはポーリング回数で測る**（2026-08-21 に直した）。
  以前はここだけフィールド数のままで、**起動が重い版では台本の 1 行目に着く前に切れて
  いた** —— しかも `exit 0` で終わるので「完走した」と読める。**打っていないのに
  通ったことになる**という、いちばん質の悪い緑だった
- `--card <path>` でメモリーカード（128KB の像）を挿す。書き換わったら書き戻す
- 疑似ビットでスティックを表現する: `LSU/LSD/LSL/LSR`（左）・`RSU/RSD/RSL/RSR`（右）
- ゴールデンは `golden.py`（Python の参照実装）が同じ画面を独立に描いて作る。
  **同じコードから作ったのでは検査にならない**ため、描画の芯は二重に書いてある

★**sim が見つけられない種類のバグがある**。GPU の FIFO を「無限・即時」でモデルして
いるので、後述の待ち合わせ不足は sim では素通りした。**実機のフィードバックが最後の砦**。

## 3. 踏んだ罠

### PS1 固有

- **`.bss` は零化されない**。PS-EXE を読み込む側は何もしてくれないので、
  `_start` の先頭で `__bss_start`〜`__bss_end` を自分で潰す
- **非アラインの `uint16` ロードが落ちる**。MojoZork の 2 箇所（`opcode_call` の
  ローカル初期化・`opcode_loadw`）が x86/ARM では動くが MIPS では誤読になる。
  `memcpy` に置き換えた（移植性バグなので upstream に報告する価値あり）
- **glibc ヘッダは `-msoft-float` を拒む**。EN/JA ビルドだけ `-mfp32` で回避
  （FP を使うコードは無いので命令は出ない）

### GPU

- ★**コマンドは待ち合わせが要る**。GPUSTAT の bit26（受付可）を見ずに連発すると、
  16 語の FIFO が溢れてコマンドが**落ちる**。スクロールを GPU の面内コピーで
  高速化したとき、19px のコピーを 21 連発して**ほぼ各行に古い帯が残った**。
  実機だけで出る（sim は無限 FIFO）
- ★**描く順序が見える**。「コピー → 露出した帯を CPU で描く（数 ms）→ 転送」だと、
  描いている間ずっと端の帯に古い画素が見えたまま走査され、**スクロール中に端がばたつく**。
  **先に描いてから、コピーと転送を隙間なく送る**と垂直帰線に収まって消える

### 描画アーキテクチャ

最初は「画面 = 巻物」で持っていたが、**遡れる量が画面数枚分しかなかった**。
テキストの履歴（`hpool` に文字列・`hline` に行の位置）で持ち、**窓の中だけを描く**形に
書き直したところ、453KB の RAM が空いて履歴は事実上無制限になった。

- 行の高さは**追加時に採寸する**（`render_dry = 1` で描かずに走らせる）。行ごとに
  ルビの有無で高さが変わるので、後から数えられない
- ★**窓より本文が短い序盤は、追記した行が「すでに窓の内側」に落ちる**。高速スクロールは
  窓の外から入ってくる分しか描かないので、この行が描かれないまま残る。積んだ位置を
  覚えて（`stale_y`）スクロール前に描き足す。**症状は打鍵ゴールデンの 2 行だけの欠け**
  として出た（自動デモでは 6 ターンの間に画面外へ流れるので通ってしまう）

### 訳の層

- ★**穴つき型の照合はバックトラックが要る**。JS は正規表現なので最右で駄目なら戻って
  次を試すが、C は「貪欲なら最右・非貪欲なら最左」を 1 回試して打ち切っていた。
  `{ECHO} {ECHO} ...`（轟音の部屋の反響）が引けず、**英語のまま出た**。
  `match_pat` を再帰にして同じ挙動にした。
  ★これは**先の修正が持ち込んだ退行**で、そのとき「その骨格は原作には無い」と
  コメントに書いていた —— **あった**。無いことの証明を書くなら数えてからにする
- ★**corpus 711 行はこの形を含んでいなかった**（`pairs.h` の echo が ASCII なので、
  かなの反響は載らない）。だから退行が素通りした。固定の検査を `test_translate.c` に足した

- ★**`{SAID}`（打った語を返す穴）は `{ECHO}` とは別のフラグ**（`TRF_SAID`）。原作が
  **入力バッファをそのまま印字**する行（`NOT-HERE-PRINT` / `THING-PRINT` → `BUFFER-PRINT`）は
  4 本あり、そこだけ訳語辞書を引かずに**打った物の表示形**を差す。
  `D ,PRSO` / `PRINTD` で**呼び名**を出している行（`(the {OBJ})` / `You don't have the {OBJ}.`）は
  括弧付きで紛らわしいが**訳す側**なので触らない
- ★**PS1 はスロット名を捨ててフラグだけ持つ**ので、`{OBJ}` → `{SAID}` に変えても
  `translate_data.c` に**差分が出ない**（フラグ 0 のまま辞書へ落ちる）。
  **「差分が無い」は「無事」ではない** —— C 側にフラグを足すまで、web だけが直っていた
- ★**打った物の表示形は `CmLex.fo`（form）**。`disp` は「この物を**何と呼ぶか**」、
  `form` は「**打った人が何と打ったか**」で別物。`cmd.c` の `Tok` にも同じ組を足すこと
  （lex と Tok は別の構造体 —— 片方だけ足すとコンパイルが止まる。止まるだけ良心的）
- ★**等価性の検査（`corpus.txt` 3,921 件）が JS 側の抜けを見つけた。** `said` を C と JS の
  両方の出力に足したら 224 件食い違い、原因は**JS が「〜以外をとる」で `prso` を手組みしていて
  `form` を書き忘れていた**こと。**移植は元実装の検査になる**

### Z-machine

- **1.3KB の文字列でフリーズした**。Zork I の最長段落（ダムの案内書）が
  `print_zscii` のスタックバッファ 512 を超えて `malloc` 経路へ落ち、
  当時スタブだった malloc が NULL を返して die ループに入っていた。
  バッファを 2048 に広げ、`lib.c` に LIFO アリーナ malloc も実装（二重の安全）。
  ★**症状の一致は原因の一致ではない**——「案内書で止まる」という同じ症状で、
  最初は canvas 溢れだと誤診した

## 4. 入力（PS1 での適応）

土台は GamepadEngine の状態機械そのまま（ゴールデン 35 件）。ただし**実機で触ると
決まること**がいくつもあり、実機フィードバックのたびに次を変えた。

| 変更 | 理由 |
|---|---|
| L2 の「対象外なら っ」を捨てる | 意図せず入る。っ は L2+R2 で明示的に打てる |
| R2 長押しの BS はリピートしない | 打ち間違いは 1 字消せば足りる |
| や行の「」・わ行の？を空ける | コマンドに要らない |
| わ行を**フリックと同じ並び**に（中央=わ / 左=を / 上=ん / 右=ー） | 同じ作品の別の入り口で並びが違うのは通らない。ゐ・ゑ は落とす |
| コマンド欄の右端は数字でなく「abc」等 | 数字より文字群のほうが引ける |
| その字群を**小文字**にする | ゲームが打ち返す語は必ず小文字（下記） |
| 英語面で L2 のシフト／CapsLock を殺す | 大文字に用が無い。しかも誤爆していた（下記） |
| 英語面の記号を Zork の辞書に合わせる | 元の表は `.` `,` を持たず、要らない記号ばかりだった（下記） |

**アナログスティック**（GIME の `gamepad-mapping.md` から移植）:

| | 日本語 | 英語 |
|---|---|---|
| 右スティック ↑ | 濁点/半濁点トグル | —— |
| 右スティック ← | BS | BS |
| 右スティック → | 長音「ー」 | —— |
| 右スティック ↓ | 確定 | 確定 |
| 左スティック ↑↓ | 履歴スクロール | 同左 |
| 左スティック ←→ | キャレット移動 | 同左 |
| L3 / R3 押込み | 確定 / 入力行クリア | 同左 |

倒し込みで 1 回だけ発火し、ニュートラルに戻るまで再発火しない（閾値 0.5・GIME と同じ）。
スティック入力が入ると R2 の「ん→を→んを」循環は切れる（GIME 準拠）。

★**英語 T9 の方角ショートカットは偶然よくできている**。n は "mno" の 2 番目 = 上（△）、
s は "pqrs" の 4 番目 = 下（×）、w は "wxyz" の先頭 = 左（□）で、**方角と一致する**。
e だけは "def" の 2 番目 = 上に行くので外れる。

### 英語面を Zork に合わせる（2026-08-27）

土台の `GP_ENG` は GIME 汎用の英語 T9 で、**Zork 用ではなかった**。zork1.z3 の辞書
684 語と、`zm_host_test` での実挙動を突き合わせて次を確かめた。

| 字 | 要る？ | 根拠（実測） |
|---|---|---|
| `,` | **要る** | 目的語の並列・呼びかけ。`take leaflet, mailbox` → `Taken.` |
| `.` | 要らない | 文は切れるが**後半は捨てられる**。`open mailbox. read leaflet` は前半だけ。つなぐのは `then` |
| `"` | 要らない | `hello sailor` が素で通る。`say "hello sailor"` はむしろ `Say what?` |
| `-` | 要らない | `air-pump` / `hand-held` / `trap-door` は `door` 等が単独でも引ける |
| 数字 | 要らない | 辞書で数字を含むのは `pdp10` と `h2o` の 2 語だけ |
| `#` | 要らない | デバッグ 4 語（`#comm` `#rand` `#reco` `#unre`）のみ |

ところが元の表は **`.` も `,` も持たず**、`( ? ) ! @ # - _` だけを載せていた。
そこで `zork_sym()`（`main.c`）で差し替える。`tables.h` は `gen_tables.py` の
生成物なので触らない。

```
row 0（方向キーなし）  R1:1  □:.  △:,  ○:-  ×:空白
row 9（L1+↓）         R1:0  面ボタンは空
```

★**空白を面ボタンに置いたのが本体**。SELECT は打鍵の流れから外れた位置にあり、
`.` `,` と並べて 1 押しで出せるほうが速い（SELECT の空白は残してある）。
これで右スティック ↓ が空くので、**日本語と同じ「確定」**に揃えた。

★**図を描く側も同じ `zork_sym()` を通す**（`grid_cell`）。`help_draw` は `gp_cell` を
直に読んでいたので、差し替えると**図だけ旧記号のまま**になるところだった。
空白は字として見えないので図では `_` を立てる（同梱フォントに `␣` が無い）。

#### 小文字にした理由

**ゲームが打ち返す語は必ず小文字で出る**。`gparser.zil` の `WORD-PRINT` は入力バッファ
（`P-INBUF`）を `PRINTC` でそのまま吐き、その手前で `mojozork.c` の `read` がバッファを
小文字化する。指標や入力を大文字にすると、未知語のときに

```
>FROBOZZ
I don't know the word "frobozz".
```

と**同じ語が 2 つの字面で 2 行差に並ぶ**。本文も混ぜ書きなので入力行だけ全大文字は浮く。

#### L2 のシフトを殺した理由

Zork の辞書は全部小文字で、`read` が小文字化するので**大文字に用が無い**。加えて
L2 は**履歴スクロールの修飾キーを兼ねている**ため、遡るたびにシフト機構を踏んでいた:

- `input.c` — L2 を 500ms 以上握ると `engCapsLock` が**勝手にトグルする**
- `input.c` — 短く押して離すと `engShiftNext` が立ち、**次の 1 文字だけ大文字**になる

どちらも状態が画面に出ないので「たまに勝手に大文字になる」ようにしか見えなかった。
止めるのは**呼び出し側**（`GpFrame` の `ltNow` に 0 を渡す）。`input.c` は `machine.ts`
と同一に保つ。

## 5. 言語の統合

英語版と日本語版を `main.c` に畳んだ。**Z-machine と story は 1 つだけ持ち**、
ステータス行・出力の訳・入力方式だけを `lang_en` で分岐する。

★**この形にしたので、ゲームの状態は言語に依存しない**。セーブを実装すれば
「英語で保存 → リセット → 日本語で再開」がそのまま通る（Z-machine の状態を
受け渡すだけで、訳は出力の側にしか関わらないため）。同じ理由で、その気になれば
**遊んでいる途中に言語を切り替える**ことも作れる。

## 6. セーブ（メモリーカード）

`card.c` がカードの読み書き、`main.c` の `zm_save` / `zm_restore` が状態の梱包。
プロトコルは psx-spx の Read/Write Frame（装置 81h・1 フレーム 128 バイト）をそのまま写した。

- ★**枠は 1 つだけ**。名前やスロットを訊く画面を出すと「コントローラだけで遊べる」が
  壊れる（ブラウザ版 `src/glk-shim.js` の `SLOT` と同じ判断）
- ★**保存するのは動的メモリ・スタック・`bp`・PC の 4 つだけ**。訳も入力方式も状態では
  ないので、**英語で保存して日本語で再開してもそのまま続く**
- 動的メモリ 11,282 バイトは 1 ブロック（8KB）に生では入らないので、**初期イメージとの
  XOR を RLE で畳む**（Quetzal の CMem と同じ考え）。本体が story の原本を持っている
  から比べる相手はタダ。実測で **331 バイト**（北へ 1 手の時点。上限は 7,934）
- ★**`save` は分岐を先に解決してから状態を採る**。`restore` は「save が成功した直後」へ
  戻るので、保存する PC は分岐を通った後でなければならない。失敗したら PC を巻き戻して
  偽で分岐し直す
- ★**復帰に成功すると `restore` 側の分岐は実行されない**。画面に出るのは save 側の
  「よし。」 —— Z-machine の仕様どおりで、原作の `V-RESTORE` にある `V-FIRST-LOOK` は
  呼ばれない
- ★**フォーマットはしない**。ヘッダが `MC` でなければ失敗を返す。フォーマットは他人の
  セーブを消す操作なので、ゲームが黙ってやってよいことではない
- BIOS の管理画面に出る名前は「ぜんまい」、絵は 16×16 の渦巻き（`gen_icon.py`）。
  ★**作品名は入れない**（README「商標の姿勢」をセーブ画面にも通す）

検証は `sh test-save.sh`（5 件）。カード層の往復・BIOS が読める形か・実ゲームでの
「ほぞんする」→「さいかいする」の往復・★**セーブが無ければ戻らないこと**（カナリア）。
台本は `save_move_ja.script` / `restore_ja.script`。

★**16×16 に渦巻きを描くとき、8 近傍の縁取りを付けたら渦が塗り潰されて消えた**。
線の間隔が 1〜2 画素しかないため。BIOS は黒背景なので明るい線だけで足りる。

## 7. オプション（メニューと 3 つの頁）

入口は ★**コマンドを打っていないときの Start**。Start は入力中は確定、Select は濁点 /
空白で埋まっているので、**空いていたのはここだけ**だった(実測して確かめた)。

かたちは **本文に重ねる小さなメニュー → 行き先は全画面の頁**。メニューは道しるべであって
目的地ではないから軽い板で足り、行き先は読み物だから画面を占める。

| 場面 | ボタン |
|---|---|
| 本文（打っていないとき） | Start = 開く |
| メニュー | ↑↓ 選ぶ / **面ボタンどれでも** きめる / Start とじる |
| 頁 | ↑↓・L1/R1 = **頁送り** / 面ボタン 一段もどる / Start 一足で本文へ |
| ひらがな入力方法 | **面ボタンは字を出す側**なので戻らない。出口は Start だけ |

- ★**案内は画面に書かない**。「Start で開いたら Start で閉じる」「開いた先で面ボタンを
  押せば決まる」は当時から浸透している作法で、書くと画面がその分だけ狭くなるだけだった。
  だから決定を ○/× で言語ごとに入れ替える必要も消えた（**作法に乗るほうが地域差より強い**）
- ★**枠線は引かない**。地色（本文 = 黒 / オプション = 濃い藍 `0x1C62`）だけで区別が付く。
  言語メニューも同じ藍にして「本文か、それ以外か」を色の一点で示す
- ★**画面に出る文字列は全部こちらのもの**で、原作の文は 1 つも出ない。だから訳の表は
  通さず完成行で持つ(`gen_ui.py`)
- ★**別ループを回さない**。開いている間の 1 フレーム分を対話ループの中で処理し、
  **パッドを読む場所を 1 つに保つ**
- ★**地色は転送で塗る**（`paint_screen`）。GPU のフィルと CPU 転送は別経路なので、
  混ぜると地色がわずかに食い違って見えた（実機で見えた。sim では同一に出る）

### 頁 1: ひらがな入力方法（コントローラの図 + 試し打ち）

本文を持たず、**押している状態がそのまま図に出る**（web 版と同じ考え方）。

- 札は入力表から引く（`gp_cell`）。★**図に出ている字と実際に入る字が違う**が最悪の事故
- 行/段の割り出しは `pad_row` / `pad_vowel` に切り出し、**図と入力で同じ式**を使う
- 押しているものは**面を塗って字を抜く**。字の色だけでは藍の上で差が小さすぎた
- ★試し打ちは**本文と同じ入力の道をそのまま通す**。器（`comp`）も本物と同じで、頁に
  入るときに空にするだけ。`options_step` が 2 を返して横取りを止め、下の入力処理へ落ちる。
  欄の絵も `build_strip` を共有する（地色と y だけ違う）
- ★**開けたボタンが字になった**（○ で入ると「え」が 1 字入る）。字はエッジではなく
  「押している状態」で出るので、`pad_prev` を潰すだけでは止まらない。離すまで待つ関門を置いた
- ★コマンド欄は**幅で止める**。字数（36）では止まっていたが、かなは 24px なので
  36 字 = 864px となり**欄を突き抜けて `strip[]` の外へ描いていた**

### 頁 2: システムコマンド

進行そのものへの指示（とくてん / しんだん / もういちど …）。範囲は web 版の設定ダイアログ
「システムの言葉」と同じで、**ゲームの中の行動は含めない**。
★一覧は書き写さない —— 役目の並びは `web/main.js` の `SYS` を読み、打つ言葉は asset と
`gen_cmd.PARSER_WORDS` から引く。写すと語彙を足し引きしたときに手引きだけ古くなり、
**打てない言葉を案内する**（web 版が一度そうなった、とコメントに残っている）。

### 頁 3: ライセンス

`.psexe` 1 本では外部ファイルが置けないので全文を焼き込む（MIT も zlib も「複製物に
著作権表示と全文を含める」ことを条件にしている）。折り返しは `gen_ui.py` で済ませ、
C 側は行を y に並べるだけ。★上下も**頁送り**（1 行ずつ読み進む人はいない）。

★**商標表示は「登録商標」と書かない**。Infocom の登録（Reg. 1,227,668 / 1983-02-15）は
**2003-11-22 に取り消されている**（Activision が Section 8 の更新をしなかった）。
Activision は 2023 年に Microsoft へ、原作は 2025 年に MIT で公開された。だから
画面には「Zork は Infocom の商標です／現在の権利者は Microsoft です」と出す。
★**ゲームの banner が出す `ZORK is a registered trademark of Infocom, Inc.` は
原作の文なのでそのまま**（README「商標の姿勢」= 作中の表示は原文を保持する）。

### ★ちらつきの正体は「縁の引き直し」だった

帯（幅 640）が縁を消すので、ボタンを押すたびに `page_frame()` を呼び直していた。
**帯そのものに縁を持たせれば消えない** —— 引き直しごと不要になる。原因が構造だったので、
直し方も構造で閉じた（その後、枠自体をやめたので縦の仕切りだけが残っている）。

### ★行間は本文と揃える／行数は「実機で切れないか」で決める

頁だけ「送り = 字の高さ」（24px・行間ゼロ）で組んでいたので、漢字が続く行が上下で
くっついて見えた。本文は `BASE(24) + LEAD(8) = 32` なので、頁も 32 にした。

さらに ★**行数は「画面に入るか」ではなく「実機で切れないか」で決める**。12 行だと
最下行が y=464 まで届き、**CRT では下端に貼り付いて見えた**（実機の指摘）。
11 行なら 432 で終わり、下の余白 48px は「ひらがな入力方法」の欄の下端
（`HY_STRIP + CMD_H` = 432）とも揃う。上 40px / 下 48px でオーバースキャンの内側。
★**入る行数が減る**（14 → 11）ので、`PAGE_ROWS` と、頁送りを見張っている
`test-options.sh` の期待値もセットで直す。

★**sim では気づけない種類**（画素は正しく出ている）。実機のフィードバックが最後の砦、の 3 例目。

### ★起動メニューは 2 段に積む

`Zenmai — Zork I` と一行に並べ、その下に説明を置いていたら、**説明がどちらに掛かるのか
読めなかった**（説明は Zenmai のもので、Zork のものではない）。

- 上段 = `Zenmai` ＋ 一行の説明 ＋ **罫線で閉じる**（罫線の長さは説明の幅から出す）
- 下段 = `Zork I`（遊ぶ作品）→ 言語 → 案内

★**名前が 2 つ並ぶ画面では、どちらに何が掛かるかを配置で言う**。字面では足りない。
これに合わせて `menu_line` は **色と印を別々に受ける**ようにした
（以前は `selected` が両方を兼ねていて「印は無いが強調したい」が書けなかった）。

### ★状態行の地色は 1 段では見えない

本文（`BG` = 16,16,8）と状態行（`PANEL`）の差が **RGB555 で 1 段 = 8/255** しかなく、
実機ではまず見分けが付かなかった。2 段（32,32,24）でもまだ足りず、**3 段**の
40,40,32 で落ち着いた。本文より**明るい**側で差を付ける（暗い側だと窓の縁と
見分けが付かない）。★**暗い帯どうしの差は、思っているより大きく取らないと見えない。**

### ★頁末の空行が「1 行だけスクロール」を生む

画面に収まっているのに十字キーでカタッと下がるのは、末尾の空行が行数に入っていたから。
落とす判定は**頁 × 言語ごと**にやる —— 画面に出るのはその組み合わせで濾したあとの並びで、
「全体の末尾」だけ見ても足りない（日英の境目に置いた空行が、日本語から見ると末尾だった）。

### ★一度「本文の履歴へ流す」形で作って、作り直した

長文のスクロールも遡りも既にあるので器が要らない、という理由でそうしたが、
**実機で見た msonrm さんの指摘は「専用画面で完結し、閉じたら復帰。背景色も明確に違う」**だった。
実装が楽になる方へ寄せた判断で、**設計としては誤り**。オプションは物語ではないので、
本文と同じ紙面に置くべきではなかった。
★**「もう持っている器を使う」は、その器が同じ用途のときだけ正しい。**

### ★画面に出す字は、同梱フォントに入っていなければならない

`glyphs.h` は「使う字だけ」を焼いているので、**訳文に出てこない字は入っていない**。
そのままでは**空白で描かれる**（sim は画素を見ないので気づけない）。

- 仕組みとして、`gen_ui.py` が使った字を **`ui_chars.txt`** に書き出し、`gen_data.py` が
  それを読む。さらに ★**生成の最後に「出す字がフォントにあるか」を照合して止める** ——
  手で確かめていてはいずれ抜ける（実際、「描写」の**「写」**をこれで止めた）
- ★★**この照合には穴があった**。見ているのは「`glyphs.h` に載っているか」だけで、
  **フォントに無い字は「空白」ではなく `.notdef`（黒い四角）として載る**。載ってはいるのだ。
  実際 **`ゔ`（U+3094）が黒い四角のまま配布されていた** —— しかも `う` ＋ 濁点で**打てた**。
  `gen_data.py` 側に「焼いた字面が `.notdef` と同じなら止める」を足して塞いだ
  （私用領域 U+E000 を焼いて `.notdef` の字面を採り、それと比べる）
- いま出せない字は `WANT` に登録しておく。フォントのある環境で `glyphs.h` を作り直せば
  出せるようになる —— ★**2026-08-25 に実際にそうした**。頒布元から KH ドットフォントを
  取り直して焼き直し、`写 拗 濁 ォ` の 4 字が入った。おかげで
  **画面の言い換えが 1 つも要らなくなった**（`WANT` は空）:
  「部屋の説明を長く」→ web 版と同じ**「描写を詳しく」**、
  「KH Dot Font —— 使用書体」→ 正式名称の**「KHドットフォント —— 使用フォント」**
- ★**この照合を通せるのは gen_ui.py が持っている字だけ**。言語メニューの「日本語」は
  C に直書きしていたので照合の外にいた（`UI_LANG` に移した）。
  **画面に出る字は 1 か所に集める**、が照合の前提になる

検証は `sh test-options.sh`（17 件）。開く / 選ぶ / 面ボタンどれでも決まる / 頁送り /
一段もどる / Start で一足で戻る / 英語面でも同じ作法 / 試し打ちで字が入る /
本文へ持ち出さない / 欄は幅で止まる / わ行の並び / ★**本文が汚れない**。

### ★quit の行き先を決めていなかった

対話ループを抜けた先が `for (;;) { }` だったので、**「やめる」→「はい」がそのまま
フリーズに見えた**（実機の指摘）。いまは `_start` ごと回り直して**起動メニューへ戻る**。

- ★戻るときに **`.bss` をもう一度潰す**。「何を消すか」を数え上げる形にすると**いずれ
  数え漏らす** —— 本文の履歴・入力欄・オプションの開閉・ゲームパッドの状態機械に加えて、
  `lib.c` の LIFO アリーナ（`heap_top`）まで巻き戻す必要がある。`.bss` を潰せば
  「初期化されるもの」の定義がリンカ側と一致するので、漏れようがない。
  スタックは 0x801FFF00（`.bss` の遥か上）なので巻き込まない
- 対話ループは `noreturn` をやめて**普通に return する**（スタックも一緒に巻き戻る）
- ★**「はい」を決めた Start が、戻った先で言語の決定に化ける**。`lang_menu` の `prev` を
  `pad_read()` で始めて、押しているものは「押下済み」として引き継ぐ ——
  `interactive_en` の `pad_prev` とまったく同じ話（**押しているものはエッジではない**）。
  この形を踏むのは 3 度目（オプションが勝手に開く / 開けた ○ が字になる / これ）

検証は `sh test-quit.sh`（4 件）。★見張り方は**本文の履歴の高さ**（`total_h`）——
ゲーム中は積み上がり、起動メニューでは 0。フリーズしていれば quit 直前の値のまま止まる。
カナリアとして「quit 前は積まれていること」を先に見る（さもないと 0 は何も証明しない）。

## 7.5 フォントに対してピクセルパーフェクトか（2026-08-25 に照合した）

**している。** KH ドットフォントは TrueType のアウトラインに加えて **24px の
埋め込みビットマップ（EBLC/EBDT・ストライクは 24×24 の 1 本だけ）**を持っており、
`glyphs.h` の字面はそれと**バイト単位で一致する**（`fontTools` で全数照合）。

| | 件数 |
|---|---|
| 照合した字 | 1,391 |
| **埋め込みビットマップと完全一致** | **1,388**（送り幅も全一致） |
| フォントに字面が無い | 3 = `—`(U+2014) / `~`(U+007E) / `ゔ`(U+3094) |

- `—` は **U+2015(`―`) の字面を借りて描く**（`GLYPH_ALIAS`）。訳文にも画面にもダッシュの
  つもりで書かれているため
- `~` は焼くのをやめた。**Z-machine v3 のアルファベット表に無く、`feed_cmd` も弾く**ので
  画面に出ようがない
- `ゔ` は **う→ゔ の濁点ごと落とした**（`gen_tables.py` の PS1 適応層）。訳文にも語彙にも
  `ゔ` / `ヴ` は 1 件も出てこない。★合成（う ＋ 濁点）も試したが**この明朝は濁点を足すとき
  清音の側も描き直す**ので、「が − か」で濁点だけを取り出せない

★**同じ字は必ず同じ画素**になる（字面は 1 度だけ焼き、整数 x に置く。送りは 12/24 の整数）。
だから**同じ文字が場所によって太さを変えることは、こちら側では起こらない**。

実機で見える斜め線のがたつきは、**24px のドットフォントそのもの**（明朝なので 1px の
飾りがある）。太さのばらつきが見えるなら、疑うのは表示側 —— PS1 の出力は
**640×480 インターレース**（`GP1(08) = 0x08000027`）なので、エミュレータの
インターレース処理と、パネルへの拡大が整数倍でないかどうかで、1px の線の出かたが変わる。

GitHub Releases にタグを切って `.psexe` を添付する（`ps1-v1.0.0` 〜。最新は `ps1-v1.2.1`）。
★ビルドは再現する（毎回タグから建て直して md5 を照合している）。版の中身を差し替えず、
**新しいタグを切る**こと。

★**リポジトリは 2026-08-26 に public にした。** 公開前に監査して手当てしたのが以下。
判断の詳細は `native/vendor/kh-dotfont/README.md` と README のライセンス節。

- ★**同梱フォントの扱い**。`glyphs.h` はフォントの埋め込みビットマップと**バイト単位で同一**
  なので、「レンダリング結果」ではなく font software の抽出にあたる。SIL OFL 1.1 の
  条件 2（複製物に著作権表示とライセンス本文）と条件 5（一部であれ全体であれ OFL で頒布）が
  掛かるので、**OFL 全文をリポジトリと `.psexe` の両方に置き**、README で
  **`native/glyphs.h` だけは MIT ではなく OFL** と切り出した。
  ★**MIT と zlib は全文を焼いていたのに OFL だけ名前しか出していなかった** ——
  「`.psexe` 1 本では外部ファイルを置けないから全文を焼く」という理屈は 3 つとも同じなのに、
  1 つだけ揃っていなかった（`ps1-v1.2.1` はこの手当てだけの版）
- 秘密情報は作業ツリー・**全履歴の blob 走査**とも 0 件。`zork1.z3` は upstream と md5 一致
- 私的な参照（一時ディレクトリの絶対パス・非公開メモへの wiki リンク・別プロジェクトの
  ローカルパス）を落とした。★**訳と語彙の原簿は非公開リポジトリのまま**なので、
  「このリポジトリ単体では `assets/*.json` を作り直せない」と `docs/overview.md` に明記した
