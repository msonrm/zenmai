# Zenmai PS1 版 実装ノート

**状態: 段階 1〜4 完了・遊べる**（2026-08-21）。計画は `ps1-port-plan.md`、こちらは
**実際に作って分かったこと**を置く。計画に書いてあって変えなかったことは繰り返さない。

配布物は `ps1/zenmai-zork.psexe`（起動時に にほんご / ENGLISH を選ぶ統合版・628KB）。
残る段階は **5. セーブ（メモリーカード）** と **6. 実機 CRT** の 2 つだけ。

## 1. どう組んだか

`psyqo` も pcsx-redux も使わなかった。**フリースタンディングの C を直接 PS-EXE に固める**
形（`link.ld` + `pack_exe.py`）で、SDK 依存はゼロ。理由は、要るものが GPU への
コマンド送出とパッド読みだけで、SDK を入れるほうが遠回りだったから。

| 層 | ファイル | 出どころ |
|---|---|---|
| 描画・パッド | `render.c` / `render.h` | 新規 |
| ルビ分節 | `jp_text.c` | web の `ruby.js` を移植 |
| 訳 | `translate.c` + `translate_data.c` | web の `translate.js`（JS が正典） |
| かな → コマンド | `cmd.c` + `cmd_data.c` | web の `command.js`（同上） |
| 入力状態機械 | `input.c` + `tables.h` | GamepadEngine の `machine.ts` |
| Z-machine | `vendor/mojozork.c` | MojoZork f94c3104（zlib）+ パッチ |
| mini-libc | `lib.c` | 新規（mem/str・vsnprintf・LIFO アリーナ malloc） |
| 統合版 main | `zm_dual_main.c` | —— |

`_data.c` 系は `gen_*.py` が web の資産から生成する。**JS 側が正典**なので、訳や語彙を
直したいときは web を直してから再生成する（配布物だけ直すと次の生成で戻る）。

★**生成ヘッダはリポジトリに追跡している**。`glyphs.h` は KH ドットフォント（同梱していない）
が無いと作れないので、無視すると clone しただけではビルドできなくなる。

## 2. 検証リグ —— R3000 シミュレータ

実機もエミュレータも自動検証には使えないので、**`sim.py` に MIPS I を手書きした**。
命令の実行に加えて GPU コマンド列（`0xA0` 転送・`0x02` 塗り・`0x80` 面内コピー）を
解釈して仮想 VRAM を組み立て、最終画面を PNG にする。`--expect` でゴールデンと画素比較。

```
sim.py zenmai-zork.psexe --script dual_ja.script --polls --stop 200000 --png out.png
```

- **台本の時間軸は `--polls`（パッドのポーリング回数）にする**。フィールド数だと処理の
  重さで台本がずれる。ポーリング回数は「ゲームが入力を待っている回数」なので、
  変換に時間がかかっても台本は追従する（閉ループ）
- 疑似ビットでスティックを表現する: `LSU/LSD/LSL/LSR`（左）・`RSU/RSD/RSL/RSR`（右）
- ゴールデンは `golden.py`（Python の参照実装）が同じ画面を独立に描いて作る。
  **同じコードから作ったのでは検査にならない**ため、描画の芯は二重に書いてある

★**sim が見つけられない種類のバグがある**。GPU の FIFO を「無限・即時」でモデルして
いるので、後述の待ち合わせ不足は sim では素通りした。**実機のフィードバックが最後の砦**。

## 3. 踏んだ罠

### PS1 固有

- **`.bss` は零化されない**。PS-EXE を読み込む側は何もしてくれないので、
  `_start` の先頭で `__bss_start`〜`__bss_end` を自分で潰す
- **非アラインの `uint16` ロードが落ちる**。MojoZork の 2 箇所（`opcode_call` の
  ローカル初期化・`opcode_loadw`）が x86/ARM では動くが MIPS では誤読になる。
  `memcpy` に置き換えた（移植性バグなので upstream に報告する価値あり）
- **glibc ヘッダは `-msoft-float` を拒む**。EN/JA ビルドだけ `-mfp32` で回避
  （FP を使うコードは無いので命令は出ない）

### GPU

- ★**コマンドは待ち合わせが要る**。GPUSTAT の bit26（受付可）を見ずに連発すると、
  16 語の FIFO が溢れてコマンドが**落ちる**。スクロールを GPU の面内コピーで
  高速化したとき、19px のコピーを 21 連発して**ほぼ各行に古い帯が残った**。
  実機だけで出る（sim は無限 FIFO）
- ★**描く順序が見える**。「コピー → 露出した帯を CPU で描く（数 ms）→ 転送」だと、
  描いている間ずっと端の帯に古い画素が見えたまま走査され、**スクロール中に端がばたつく**。
  **先に描いてから、コピーと転送を隙間なく送る**と垂直帰線に収まって消える

### 描画アーキテクチャ

最初は「画面 = 巻物」で持っていたが、**遡れる量が画面数枚分しかなかった**。
テキストの履歴（`hpool` に文字列・`hline` に行の位置）で持ち、**窓の中だけを描く**形に
書き直したところ、453KB の RAM が空いて履歴は事実上無制限になった。

- 行の高さは**追加時に採寸する**（`render_dry = 1` で描かずに走らせる）。行ごとに
  ルビの有無で高さが変わるので、後から数えられない
- ★**窓より本文が短い序盤は、追記した行が「すでに窓の内側」に落ちる**。高速スクロールは
  窓の外から入ってくる分しか描かないので、この行が描かれないまま残る。積んだ位置を
  覚えて（`stale_y`）スクロール前に描き足す。**症状は打鍵ゴールデンの 2 行だけの欠け**
  として出た（自動デモでは 6 ターンの間に画面外へ流れるので通ってしまう）

### Z-machine

- **1.3KB の文字列でフリーズした**。Zork I の最長段落（ダムの案内書）が
  `print_zscii` のスタックバッファ 512 を超えて `malloc` 経路へ落ち、
  当時スタブだった malloc が NULL を返して die ループに入っていた。
  バッファを 2048 に広げ、`lib.c` に LIFO アリーナ malloc も実装（二重の安全）。
  ★**症状の一致は原因の一致ではない**——「案内書で止まる」という同じ症状で、
  最初は canvas 溢れだと誤診した

## 4. 入力（PS1 での適応）

土台は GamepadEngine の状態機械そのまま（ゴールデン 35 件）。ただし**実機で触ると
決まること**がいくつもあり、実機フィードバックのたびに次を変えた。

| 変更 | 理由 |
|---|---|
| L2 の「対象外なら っ」を捨てる | 意図せず入る。っ は L2+R2 で明示的に打てる |
| R2 長押しの BS はリピートしない | 打ち間違いは 1 字消せば足りる |
| や行の「」・わ行の？を空ける | コマンドに要らない |
| わ行う段に「ー」を置く | 長音が打てなかった |
| コマンド欄の右端は数字でなく「ABC」等 | 数字より文字群のほうが引ける |

**アナログスティック**（GIME の `gamepad-mapping.md` から移植）:

| | 日本語 | 英語 |
|---|---|---|
| 右スティック ↑ | 濁点/半濁点トグル | —— |
| 右スティック ← | BS | BS |
| 右スティック → | 長音「ー」 | —— |
| 右スティック ↓ | 確定 | 空白 |
| 左スティック ↑↓ | 履歴スクロール | 同左 |
| 左スティック ←→ | キャレット移動 | 同左 |
| L3 / R3 押込み | 確定 / 入力行クリア | 同左 |

倒し込みで 1 回だけ発火し、ニュートラルに戻るまで再発火しない（閾値 0.5・GIME と同じ）。
スティック入力が入ると R2 の「ん→を→んを」循環は切れる（GIME 準拠）。

★**英語 T9 の方角ショートカットは偶然よくできている**。n は "mno" の 2 番目 = 上（△）、
s は "pqrs" の 4 番目 = 下（×）、w は "wxyz" の先頭 = 左（□）で、**方角と一致する**。
e だけは "def" の 2 番目 = 上に行くので外れる。

## 5. 言語の統合

英語版と日本語版を `zm_dual_main.c` に畳んだ。**Z-machine と story は 1 つだけ持ち**、
ステータス行・出力の訳・入力方式だけを `lang_en` で分岐する。

★**この形にしたので、ゲームの状態は言語に依存しない**。セーブを実装すれば
「英語で保存 → リセット → 日本語で再開」がそのまま通る（Z-machine の状態を
受け渡すだけで、訳は出力の側にしか関わらないため）。同じ理由で、その気になれば
**遊んでいる途中に言語を切り替える**ことも作れる。
